## 3. Corpus reproduction

The page images are not redistributed in this repository (see `DATA_NOTICE.md`); they can be regenerated byte-identically from the pinned source revisions:

```bash
python3 -m venv .venv && .venv/bin/pip install -r runtime/requirements.lock
# fetches the two datasets at the pinned revisions and exports
# data/images/ + data/ground_truth/ byte-identically, then verifies row counts:
.venv/bin/python runtime/scripts/fetch_datasets.py
```

`scripts/fetch_datasets.py` (in `runtime/`) pins revisions in code (`benchmark/constants.py`), exports original image bytes with no re-encode, writes ground truth unmodified, and regenerates `manifests/export_records.json` (per-page source row/UUID + SHA-256 of image and GT). After fetching, verify every file against the manifest:

- 462 `image_sha256` and 462 `ground_truth_sha256` entries in `manifests/canonical_manifest.json` must match the files on disk.
- The published `ground_truth/` directory in this repo must match those same 462 GT hashes.

Both checks passed for this release (462/462 GT and 462/462 images verified against the frozen manifest).

## 4. Re-running a model

The runner is the code in `runtime/` (unmodified):

```bash
# GPU environment (L40S-class):
python3 -m venv .venv-gpu
.venv-gpu/bin/pip install --extra-index-url https://download.pytorch.org/whl/cu128 -r runtime/requirements-gpu.lock
.venv-gpu/bin/python runtime/scripts/predownload_models.py   # pull pinned weights
.venv-gpu/bin/python runtime/scripts/run_official.py --help  # per-model run entrypoint
```

Protocol facts a re-run must preserve (all recorded in `METHODOLOGY.md`, the registry YAMLs, and each `run_state.json`): byte-identical images, the model's documented prompt verbatim, pinned revisions, greedy decoding with the recorded per-run generation parameters, bf16, no quantization/offload, one model at a time, 462 pages in manifest order, atomic per-page records, normalization policy v1.0.0 applied identically to prediction and GT, macro-mean aggregation.

## 5. Recomputing the leaderboard from stored records (no inference)

All quality numbers in this release can be recomputed from `results/per_page_records/` + `ground_truth/` alone, using the canonical scorer in `runtime/benchmark/`:

```python
# with runtime/ on sys.path, e.g. inside the extracted repository root
import json, glob, sys
sys.path.insert(0, "runtime")
from benchmark.metrics.aggregate import aggregate_run, score_page

for run_dir in sorted(glob.glob("results/per_page_records/*__full__*")):
    records = [json.load(open(p, encoding="utf-8"))
               for p in glob.glob(f"{run_dir}/*.json") if not p.endswith("run_state.json")]
    gt = {r["page_id"]: open(f"ground_truth/{gt_subpath(r['page_id'])}", encoding="utf-8").read()
          for r in records if r["status"] == "PASS"}
    pages = [{"status": r["status"],
              "metrics": score_page(gt[r["page_id"]], r["raw_output"] or "")} for r in records]
    print(run_dir.split("/")[-1], aggregate_run(pages))
```

`gt_subpath` maps `MISRAJ-*` → `Misraj-DocOCR/<id>.md` and `KITAB-R-*` → `KITAB_pdf_to_markdown_reviewed/<id>.md` (as recorded in the manifest's `ground_truth_path`). The stored per-page `metrics` fields in the records were computed by this exact code path at run time; the stored aggregate reports in `results/reports/` were computed from them by `runtime/benchmark/reporting/reports.py`.

### Independent verification performed for this release

Before publication, every number was re-verified offline:

1. **Manifest:** page count 462, 462 unique IDs (400/62 split), SHA-256 match with the declared value.
2. **Files:** all 462 ground-truth files and all 462 page images hash-match the manifest.
3. **Records:** for every full/partial run across both sessions — record set exactly matches the manifest (or, for partial runs, is a prefix of the frozen queue plus a stop record); no duplicate IDs; no GT field embedded in any record; `model_revision` matches the registry pin; manifest hash in each `run_state.json` matches.
4. **Metrics:** an independent re-implementation of the canonical scorer (Levenshtein CER/WER + normalization policy v1.0.0) recomputed all four metrics for all 3,068 PASS page records: **max per-page |Δ| = 0.0** against the stored metrics. Recomputed `normalize_text(raw_output)` matched every stored `normalized_output`, and every `results/normalized/` file byte-matched its record.
5. **Aggregates:** recomputed macro-means (manifest order) matched the stored reports in `results/reports/` to within float epsilon (max |Δ| ≈ 2.2e-16; the resumed-session AIN run matched its stored report to ≤ 8.9e-16); partial-run aggregates were recomputed from their stored records.
6. **Runtime fields:** the benchmark collected per-page `elapsed_seconds` and `peak_vram_mb` and per-run timing aggregates internally; these runtime fields are **redacted from this public release** (speed is out of scope — see §7). Quality metrics, statuses, and stop classifications are published in full.

## 7. Publication redactions (disclosed)

Three kinds of redaction were applied before publication; none touches any quality metric, model status, or stop classification:

1. `gpu_uuid_if_available` in every per-page record (all sessions) was **set to `null`**. The GPU **model name** (L40S / H200), dtype, timestamps, and every other non-runtime record field are unmodified.
2. Cloud-instance filesystem paths in the resumed-session orchestration evidence (`results/orchestrator_resumed/`) were replaced with `<server-root>`; the sanitized files' content (statuses, stop classifications, tracebacks, timestamps) is otherwise verbatim.
3. **All runtime/speed fields were removed** because speed is out of scope for this public release: `elapsed_seconds` and `peak_vram_mb` from every per-page record; `mean_sec_per_page`, `median_sec_per_page`, `p95_sec_per_page`, and `peak_vram_mb` from every stored aggregate report; the latency fields from the stop records; and null-valued timing blocks from the controller logs. No seconds-per-page, runtime-hours, or VRAM figure appears anywhere in this repository.

Everything else in `results/` is byte-identical to the benchmark's final state.
